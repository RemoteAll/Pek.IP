# 决策记录

## 2026-10-21 立项：Rust IP 库（Pek.IP）

### 用户原话

> 帮我增加一个Rust的IP库？要能同时支持国内和国外的。而且也最好也是按需支付，我也可以把这个打包上传到RPanel中供按需下载使用

（补充确认：`Zig.DDNS` 是 Zig 不是 Rust；继续推进 Pek.IP。）

### 背景

- 现有 Rust 生态里，国内城市级数据以 ip2region xdb 最常用，国外以 MaxMind GeoLite2/DB-IP MMDB 最常用；
- 两套数据格式、字段、IP 版本支持不同，业务侧需要一个统一结果；
- IP 数据文件较大且更新频繁，不适合编译进二进制或提交到仓库；
- 已有 Pek.RPanlServer 组件源（`/components/catalog.json` + Ed25519 签名 + zip 分发），可复用。

### 决策

1. **双数据源**
   - 国内：ip2region xdb **v3**（IPv4 / IPv6），取省/市/运营商；
   - 国外：MMDB（GeoLite2-City / GeoLite2-ASN / GeoIP2-ISP / DB-IP City）；
   - 合并：国内 IP 的省市以 xdb 为准，经纬度/时区/区县由 MMDB 补齐；国外以 MMDB 为主。
2. **不内置数据**
   - 仓库不提交 `.xdb` / `.mmdb`，避免许可与体积问题；
   - 数据由使用方按各自许可获取，或上传到 Pek.RPanlServer。
3. **按需下载**
   - 复用平台组件源协议：`{store}/components/catalog.json`（`.sig` 为 base64 Ed25519 签名）；
   - 包 SHA-256 强制校验；zip 解压防目录穿越；本地缓存 `{cache}/{id}/{version}/`；
   - `store_url` 为空 = 仅本地缓存模式；
   - `access_token` 以 `Authorization: Bearer` 发送，为后续“按需授权/付费下载”预留。
4. **数据集 id 约定**
   - `ip2region-v4` / `ip2region-v6` / `geolite2-city` / `geolite2-asn` / `dbip-city`；
   - 平台上传时分类 `ip-database`、目标平台 `any`。
5. **打包**
   - `scripts/pack-ipdb.ps1` 生成 `{id}-{version}-any.zip`，内含数据文件与 `dataset.json`；
   - 使用 .NET ZipFile `Optimal` 压缩；先写 `.new` 再替换。
6. **暂不做的事**
   - 不在本库实现订单/支付/授权校验；需要平台侧配合（见“待确认”）；
   - 暂不支持 xdb v2（明确报错，提示使用 v3 数据）；
   - 不随库分发任何数据文件。

### 待确认

1. “按需支付”是否指**付费授权下载**？若是，需在 Pek.RPanlServer 增加：
   - 组件下载的授权校验（订单/许可证/下载令牌）；
   - 客户端 `access_token` 或签名许可证校验（本库已预留 `access_token`）。
2. 平台组件包默认上限 **32 MiB**：GeoLite2/DB-IP City 压缩后可能接近/超过；是否需要放宽到 64/128 MiB？
3. 是否需要兼容旧版 xdb v2 数据？

### 本轮验证

- `cargo test`：31 项通过；
- `cargo test --all-features`：36 项通过（含组件源 Ed25519 验签 + SHA-256 + zip 下载端到端测试）；
- 真实数据：
  - `ip2region_v4.xdb`：`1.0.1.0 → 中国 福建省 福州市 中国电信`、`114.114.114.114 → 中国 江苏省 南京市`、`223.5.5.5 → 中国 浙江省 杭州市 阿里`、`8.8.8.8 → 美国 California Google LLC`、`192.168.1.1 → 局域网`；
  - MaxMind `GeoIP2-City-Test.mmdb`：`89.160.20.128 → 瑞典 Östergötland County 林雪平`（经纬度/时区由 MMDB 补齐）、`81.2.69.142 → 英国 England London`。

## 2026-10-21 数据入库、启动加载与上传教程

### 用户原话

> 仓库要有 `.xdb` / `.mmdb`这些，只是不打包进去，而是给一个教程我将这些文件上传到RPanelServer，启动时如果判断需要就先下载

### 决策

1. `data/` 随仓库提供基础数据：
   - `ip2region_v4.xdb`、`ip2region_v6.xdb`（Apache-2.0）；
   - `dbip-country-lite-2026-10.mmdb`、`dbip-asn-lite-2026-10.mmdb`（CC BY 4.0）。
2. **不打包**：`Cargo.toml` 加 `exclude = ["data/**", "dist/**", ".ref/**"]`，不使用 `include_bytes!`。
3. `scripts/fetch-data.ps1`：下载/更新 ip2region v4/v6、DB-IP Country/ASN；`-City` 下载 DB-IP City Lite。
4. `scripts/pack-ipdb.ps1`：生成 `{id}-{version}-any.zip`（含 `dataset.json`），用于上传 RPanel。
5. 新增 `IpLocator::load_or_download` + `LocatorLoadOptions`：
   - 本地 `data/` 优先；
   - 本地缓存其次；
   - 缺失时按需下载（Ed25519 + SHA-256 + zip）；
   - 默认 `allow_partial=true`，但验签/格式错误不被吞掉。
6. 新增教程 `docs/RPanel上传教程.md`（面板 + curl 两种上传方式、启动代码、更新流程）。
7. 平台组件包上限由 32 MiB 放宽到 **128 MiB**（`Pek.RPanlServer/src/components.rs`），以容纳 City MMDB。

### 说明

- DB-IP City Lite 解压后约 **121 MiB**，超过 GitHub 单文件 100 MiB 限制，默认不入库；用 `fetch-data.ps1 -City` 获取。
- `data/` 中的 `.gz` 下载包在解压后删除，仓库只保留 `.xdb`/`.mmdb`。

## 2026-10-21 下载授权/防 PCDN 协议（设计）

### 用户原话

> 有一个问题，业务系统本身是没有密钥什么之类的对接RpanelServer来下载的，要既能防疲pcdn等刷流量，但又要各业务系统又能正常下载使用，这个是不是要有个什么专门的约定算法。

### 设计结论

写入 `docs/下载授权协议.md`，按业务系统条件分档：

- **D（零密钥，推荐内部系统）**：RPanel 登记出口 IP/CIDR + 短期一次性票据；业务系统只传 `clientId`，无任何密钥；
- **B2（推荐生产/动态 IP）**：激活码 + 客户端 Ed25519 密钥对 + 平台签名 License + 5 分钟一次性下载票据；
- **B1（快速落地）**：License 内嵌 secret + HMAC；
- **C（兜底）**：PoW + 严格 IP 配额。

B2 细节：

1. 业务系统首次运行自动生成本地密钥对，管理员发一次性激活码；
2. 激活后拿到平台签名的 License（绑定客户端公钥、数据集、有效期、配额）；
3. 每次下载先请求短期票据（客户端私钥签名），票据绑定 License/数据集/版本/IP/nonce；
4. 下载 URL 带票据，服务端或 CDN 边缘校验；无票据 403；
5. 配额、并发、吊销、审计用于防批量刷流量；
6. 兜底：PoW 挑战 + 严格 IP 配额（无 License 的内部小系统）。

简化版 B1（License 内嵌 secret + HMAC）可在平台改动最小的情况下先上线，但公开网络推荐 B2。

**最终统一（2026-10-21 追加，用户指出“有可能是固定的，有可能是不固定的”）**：

- 不要求每个业务系统二选一；RPanel 按 `clientId` 配置 `authMode`：
  - `ip`：固定出口/CIDR，零密钥；
  - `key`：一次性激活码 + 本地密钥对，适配动态 IP；
  - `license`：License secret + HMAC，简单分发；
  - `public`：仅内网/调试。
- 所有模式共用 `POST /api/ipdb/ticket`；平台按 `clientId` 查模式并校验；
- 票据绑定 `clientId + dataset + version + nonce + exp`；`ip` 模式强制绑定源 IP，`key` 模式可选 `bindIp`；
- **IP 只作为票据绑定/防热链，不作为唯一身份**（NAT 共享、云主机漂移、IPv6 隐私地址都会变化）。

### 待确认

- 配额口径（每 `clientId` 每日次数/流量 vs 每 IP）？
- 是否保留 `public` 兜底（建议仅内网）？
- CDN 是否参与验票（边缘验签），还是只由 RPanel 回源校验？

### 本轮验证（更新）

- `cargo test`：31 项通过；
- `cargo test --all-features`：**42 项通过**（新增启动加载、本地优先、严格/部分模式、Config/Ip.toml 配置解析测试）；
- 真实 RPanel 端到端：
  - 临时平台 5611 上传 `ip2region-v4-2026.10.21`；
  - `IpDbManager` 拉目录 → Ed25519 验签 → 下载 zip → SHA-256 校验 → 解压安装；
  - 安装后的 xdb SHA-256 与源文件一致；
  - 离线模式（`store_url` 为空）可复用缓存并正常查询。

## 2026-10-21 自动化要求

### 用户原话

> 这个是自动的么，只有自动且安全的方案才适合我

### 决策

1. 默认 `authMode = auto`：业务系统只填 `clientId` + 平台地址，**不需要密钥/激活码**；
2. 库首次运行自动生成 Ed25519 密钥对、自动 `POST /api/ipdb/enroll`、自动拉取 License；
3. 平台按信任锚点决定是否自动批准：
   - 源 IP ∈ `AutoApproveCidrs` → 自动（内网/专线/VPC）；
   - 云 OIDC/实例身份有效 → 自动（云主机/容器）；
   - 企业 mTLS/内部 PKI 证书有效 → 自动；
   - 其它 → 管理员在面板点一次“批准”，之后全自动；
4. License 到期前自动续签，密钥按策略自动轮换；
5. **IP 只是票据绑定/防热链，不作唯一身份**；`ip` 模式可完全零密钥，`key`/`auto` 模式绑定客户端公钥；
6. “完全零人工 + 绝对安全”必须有一个信任锚点（CIDR/云身份/PKI）；没有信任锚点时，至少一次管理员批准，不提供无锚点的全自动。

### 实现默认值（待落地）

- `AutoApproveCidrs`：默认空 = 公网需一次批准；内网部署可按实际网段收紧。
- 配额：默认按 `clientId` 每日次数 + 每 IP 限速，均可配置。
- `public` 模式：默认仅内网/调试，生产建议关闭匿名 `/components/*`。
- CDN：默认 RPanel 回源验票；如接 CDN，边缘用平台公钥验票。

## 2026-10-21 业务系统零身份配置

### 用户原话

> **业务系统**我连client_id都不想配

### 决策

1. 业务系统**不配置 `clientId`**；库首次运行自动生成稳定 `installId`：
   - 随机 128 位 + 机器指纹哈希，落盘 `Data/IpClient/install.id`（0600）；
   - 平台侧自动创建客户端记录，管理员可另起可读名称/租户；
   - `clientId` 变成平台内部 ID，不暴露给业务配置。
2. 业务系统只需平台地址；平台地址固定时可用默认值，连地址也可不配。
3. 首次 `POST /api/ipdb/enroll` 自动带 `installId + clientPubKey + machineId + hostname + appName`；
4. 平台按 `AutoApproveCidrs` / 云 OIDC / 企业 mTLS 自动批准，否则管理员批准一次；
5. 安全边界：`installId` 不是密钥；安全来自本地私钥 + 平台签名 License + 短期票据 + 信任锚点。
   **没有信任锚点就不存在“零配置且安全”**；公网默认一次管理员批准，内网/云可做到零人工。
6. 配额/审计按平台内部 `clientId`（由 `installId` 映射）执行。

- 客户端 `installId` 生成、`enroll`/License 自动获取、`installId` 与机器指纹变更告警。

## 2026-10-21 自动授权落地（客户端 + 平台）

### 用户原话

> 那就继续

### 决策

1. 客户端 **`src/auth.rs`** 落地零身份自动注册：
   - 自动生成/持久化 `installId`（32 位 hex）与 Ed25519 私钥（`StateDir`，Unix 0600）；
   - `POST /api/ipdb/enroll` 注册；平台返回 pending/approved/revoked；
   - License 平台签名校验、缓存 `license.json`、到期前自动重新注册续期；
   - 每次下载用私钥签 `pek-ip-ticket-v1` 票据，向 `POST /api/ipdb/ticket` 换一次性 URL；
   - 旧平台没有授权接口 → 自动回退公开下载；授权接口 403/401 → **不回退**。
2. 平台 **`src/ipdb.rs` + `Panl_IpdbClient` 表**：
   - 自动注册（installId 唯一、公钥绑定）、`AutoApproveCidrs` 自动批准、管理员批准/吊销/恢复/删除；
   - License 365 天、剩余 <7 天自动续期；每日配额默认 20 次（内存计数，重启清零）；
   - 票据 5 分钟过期、nonce 防重放、绑定文件名 + 来源 IP；
   - 仅 `category=ip-database` 的组件包要求 `?ticket=&sig=`，其它组件保持公开；
   - 面板新增「🔐 IP 授权」页（列表/批准/吊销/恢复/删除），配置页新增 `AutoApproveCidrs` 与 `IpdbTrustProxy`。
3. 公开协议路径定为 `/api/ipdb/enroll|license|ticket|pubkey`（带斜杠），管理接口仍用 `/api/ipdbClients` 等控制器命名。
4. `Config/Ip.toml` 的 `AutoEnroll=true` 默认启用自动授权；`PubKey` 同时作为 License/票据的信任锚点（留空则首次 TOFU）。
