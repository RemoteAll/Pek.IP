# 下载授权协议（防 PCDN / 盗链刷流量）

> 背景：业务系统本身**没有预置密钥**，但 RPanel 的组件包如果完全公开，容易被 PCDN/盗链
> 直接刷流量。需要一个“不需要人工配密钥、又能限制滥用”的约定算法。

## 1. 目标与非目标

**目标**

- 业务系统首次接入**不需要人工填写密钥**（最多一个一次性激活码）；
- 下载 URL 不能长期复用/被热链；
- 可按业务系统/数据集限制下载次数、并发与流量；
- 许可证可吊销、可审计；
- 不破坏现有驱动/插件组件源（可并行存在）。

**非目标**

- 不做 DRM：拿到合法许可证的业务系统仍可在配额内下载；
- 不依赖客户端隐藏密钥（客户端可被逆向）；
- 不在本库内实现在线支付/订单（支付是平台侧独立里程碑）。

## 2. 三层方案（按强度从低到高）

| 方案 | 适用 | 是否需密钥 | 防 PCDN 强度 |
|------|------|------------|--------------|
| A. 公开目录 + 网关限流 | 内网/受控环境 | 否 | 低（只能限 IP/带宽） |
| B. 签名许可证 + 短期票据 | 生产推荐（可移植/强） | 否（激活码/自动生成密钥对） | 高 |
| D. IP 白名单 + 短期票据 | 出口 IP 固定的内部系统 | 否 | 中高（依赖 IP 可信） |
| C. PoW 挑战 + 严格配额 | 无法注册的小系统兜底 | 否 | 中（对僵尸网络有限） |

推荐：
- **内部系统、出口 IP 固定** → 先上 **D**（业务系统零密钥、平台改动小）；
- **对外/动态 IP/需要更强身份** → **B2**（激活码 + 客户端密钥对）；
- **只想快速有 License 文件** → **B1**（License secret + HMAC）；
- **完全匿名的小系统** → **C**（PoW + 严格配额）。

## 3. 方案 B：激活码 + 客户端密钥对 + 短期票据

### 3.1 首次激活（一次性）

```text
业务系统                          RPanel
   |  1. 本地生成 Ed25519 密钥对      |
   |     (私钥仅存本机)               |
   |                                |
   |  2. POST /api/ipdb/activate    |
   |     {code, clientPubKey,       |
   |      machineId, clientVersion} |
   |------------------------------->|
   |                                | 3. 校验一次性激活码
   |                                | 4. 创建 License 记录
   |  5. 返回签名 License (.lic)     |
   |<-------------------------------|
```

- 管理员在 RPanel 为业务系统创建**一次性激活码**（如 8~12 位，10 分钟有效）；
- 业务系统只需把激活码交给库（配置/环境变量），**无需手工生成/填写任何密钥**；
- 库首次运行自动生成密钥对，私钥落盘（`Data/IpClient.key`，权限 600），公钥随激活请求上报；
- License 绑定 `clientPubKey`，之后所有票据请求必须由该私钥签名。

### 3.2 License 文件（平台 Ed25519 签名）

```json
{
  "v": 1,
  "licenseId": "lic_7f3a...",
  "tenant": "业务系统标识",
  "datasets": ["ip2region-v4", "ip2region-v6", "dbip-city", "geolite2-asn"],
  "notBefore": 1790000000,
  "notAfter": 1820000000,
  "maxDownloadsPerDay": 20,
  "maxConcurrent": 2,
  "clientPubKey": "<Ed25519 公钥 hex>",
  "issuedAt": 1790000000,
  "signature": "<平台 Ed25519 对上面字段规范化 JSON 的 base64 签名>"
}
```

客户端用平台公钥（`IpDbManagerConfig.pubkey`）验签；License 中的 `datasets` 决定可下载的数据集。

### 3.3 票据请求（客户端私钥签名）

```http
POST /api/ipdb/ticket
Content-Type: application/json

{
  "licenseId": "lic_7f3a...",
  "dataset": "ip2region-v4",
  "version": "2026.10",
  "nonce": "<随机 16 字节 hex>",
  "ts": 1790000123,
  "signature": "<Ed25519 base64>"
}
```

签名原文（**约定算法**，UTF-8、`\n` 分隔、字段不可调换）：

```text
pek-ip-ticket-v1
{licenseId}
{dataset}
{version}
{nonce}
{ts}
```

服务端校验：

1. License 存在、未吊销、在有效期内、包含该 dataset；
2. `clientPubKey` 验签通过；
3. `ts` 与服务端时间偏差 ≤ 5 分钟；
4. `nonce` 未使用过（短期缓存）；
5. 当日下载次数/并发未超限。

### 3.4 票据响应（平台签名）

```json
{
  "code": 0,
  "data": {
    "url": "/components/ip2region-v4-2026.10-any.zip?ticket=...",
    "expires": 1790000423
  }
}
```

票据 payload（base64 JSON，平台签名）：

```json
{
  "v": 1,
  "licenseId": "lic_7f3a...",
  "dataset": "ip2region-v4",
  "version": "2026.10",
  "fileName": "ip2region-v4-2026.10-any.zip",
  "clientIp": "203.0.113.10",
  "nonce": "<随机>",
  "exp": 1790000423,
  "maxBytes": 134217728
}
```

下载：

```http
GET /components/ip2region-v4-2026.10-any.zip?ticket=<base64(payload)>&sig=<base64>
```

服务端（或 CDN 边缘函数）校验签名、`exp`、`clientIp`、`fileName`、一次性 nonce、配额后流式返回。
**票据 TTL 建议 5 分钟，一次性使用**；过期/换 IP/重放均拒绝。

### 3.5 防 PCDN 刷流量要点

| 攻击 | 防护 |
|------|------|
| 热链/盗链公开 URL | 包地址必须带短期票据；无票据 403 |
| 票据转发 | 票据绑定 License + 客户端 IP + 一次性 nonce + 5 分钟 TTL |
| License 文件泄露 | License 绑定客户端公钥；私钥不离开业务服务器；可吊销 |
| 批量刷下载 | 每 License 日/月配额、并发上限、单 IP 限速 |
| 伪造客户端 | 激活码一次性 + 公钥绑定 + 服务端验签 |
| CDN 回源绕过 | 票据在边缘验签；或只允许 RPanel 回源并校验 |
| 许可证滥用 | 审计日志（License/IP/数据集/字节数）、异常告警、吊销/轮换 |

### 3.6 方案 D：IP 白名单 + 短期票据（零密钥，推荐内部系统）

如果业务系统**完全不想/不能持有任何密钥**，但出口 IP 相对固定（公司机房/云主机固定公网 IP/NAT 网关），
可用“IP 白名单 + 短期票据”：

1. 管理员在 RPanel 登记业务系统：`clientId`、出口 IP/CIDR、可下载数据集、日配额；
2. 业务系统**无需任何密钥**，直接请求票据：

   ```http
   POST /api/ipdb/ticket
   { "clientId": "billing", "dataset": "ip2region-v4", "version": "2026.10" }
   ```

3. 平台按 TCP 源 IP 匹配白名单（不是 HTTP 头里的 `X-Forwarded-For`，除非可信反代已清洗），
   通过后返回 5 分钟一次性票据；票据绑定 `clientId + dataset + version + 源 IP + nonce`；
4. 下载 URL 带票据，服务端/边缘校验；换 IP/过期/重放均拒绝；
5. 配额、并发、审计同 B。

优点：业务系统零密钥、零改造；缺点：依赖固定出口 IP，NAT 共享/动态 IP 场景需配合 B2。

### 3.7 为什么不用“固定 AppKey/Secret”？

- 固定密钥写进业务系统/库 = 可被提取，所有部署共享，泄露即全量失守；
- 需要人工分发/轮换，业务系统“没有密钥”场景无法落地；
- 激活码 + 本地生成密钥对：**一次性人工成本**，之后无共享密钥，泄露面最小。

## 4. 方案 B1：简化版（License 内嵌 secret + HMAC）

如果不想做“激活码 + 客户端密钥对”，可先用更简单的 B1：

- 管理员在 RPanel 创建 License，平台生成 `.lic`（含 `secret`，平台签名）；
- 业务系统拿到 `.lic`（一个文件，无需手工配密钥）；
- 票据请求用 `HMAC-SHA256(secret, 约定原文)` 代替 Ed25519 签名；
- 服务端用 License 中的 secret 验 HMAC。

优点：平台改动小（无需存客户端公钥/激活码）。
缺点：`.lic` 即凭据，泄露后可被复制使用；靠配额/吊销/IP 绑定缓解。
适合内部/可信分发；公开网络推荐 B2（客户端密钥对）。

## 5. 方案 C：PoW 匿名兜底（无 License）

用于无法注册的内部小系统：

1. `GET /api/ipdb/challenge` → `{challenge, difficulty}`（如 20 bit）；
2. 客户端寻找 nonce，使 `SHA256(challenge|nonce)` 前 `difficulty` 位为 0；
3. `POST /api/ipdb/ticket` 提交 solution → 短期票据；
4. 每 IP 严格日配额 + 并发限制 + 带宽限速。

优点：零配置；缺点：PCDN 僵尸网络仍可分摊成本，只能作为兜底，不能替代 License。

## 6. 客户端 API 设计（待落地）

```rust
pub struct IpDbManagerConfig {
    // ... 现有字段
    /// 平台签发的 License 文件（.lic）；None = 未授权
    pub license_file: Option<PathBuf>,
    /// 客户端私钥文件（首次自动生成）；None = 使用默认 Data/IpClient.key
    pub client_key_file: Option<PathBuf>,
    /// 首次接入的一次性激活码；激活成功后写回 License，之后可移除
    pub activation_code: Option<String>,
}

impl IpDbManager {
    /// 有 License：走票据下载；无 License：按配置回退公开下载或报错
    pub fn ensure_authorized(&self, dataset_id: &str) -> Result<InstalledDb>;
}
```

启动流程：

```text
load_or_download
  ├─ 本地 data/ 有 → 直接用
  ├─ 本地缓存有 → 直接用
  ├─ 有 License → 请求票据 → 带票据下载
  ├─ 有激活码 → 激活 → 保存 License → 请求票据
  └─ 都没有 → 按 allow_public_fallback 决定：公开下载 / 跳过 / 报错
```

## 7. 平台侧改造清单（Pek.RPanlServer）

1. 表：
   - `IpdbLicense`（LicenseId/Tenant/ClientPubKey/Datasets/NotBefore/NotAfter/Quota/Status/…）
   - `IpdbActivation`（Code/Expires/Used/LicenseId/…）
   - `IpdbDownloadLog`（LicenseId/Dataset/Bytes/Ip/Time/…）
2. 端点：
   - `POST /api/ipdb/activate`（公开，激活码 + 公钥）
   - `POST /api/ipdb/ticket`（公开，License + 签名）
   - `GET/POST /api/ipdb/licenseList|licenseCreate|licenseRevoke`（管理员）
3. `/components/{file}`：对 `category=ip-database` 的包强制票据；其他组件保持现状（向后兼容）。
4. 面板新增「IP 数据授权」页：创建 License、生成激活码、配额/吊销/下载审计。
5. 票据签名私钥复用平台 `Config/plugin-store.key`（Ed25519），客户端公钥已配置。

## 8. 建议与待确认

- **出口 IP 固定、完全不想碰密钥** → 先做 **D（IP 白名单 + 短期票据）**：平台改动最小，
  业务系统只需调一个 `POST /api/ipdb/ticket`（带 `clientId`），无任何密钥。
- **需要可移植/更强身份**（动态 IP、云函数、多租户）→ **B2**：激活码 + 客户端密钥对 + License + 5 分钟票据。
- **只想快速有 License 文件** → **B1**（License secret + HMAC），平台改动小，但 `.lic` 即凭据。
- **完全匿名的小系统** → **C**（PoW + 严格配额），只建议兜底。
- 公开目录/包地址是否保留？建议保留但仅用于内网/调试，生产通过反向代理关闭匿名 `/components/*`。
- 需要确认：
  1. 业务系统出口 IP 是否固定/可登记？固定 → D 最快；不固定 → B2。
  2. 若选 B2，是否接受首次接入需要一个一次性激活码（可批量生成/导入）？
  3. 配额口径（每 License/每 IP 的每日次数或流量）？
